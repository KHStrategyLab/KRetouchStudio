## Review Findings

### Tab Reset Semantics

- Face Shape and Face Detail reset currently restore the image snapshot from before the first active tab effect.
- If another retouch operation was applied afterward, that later work can also be removed.
- The intended contract is a new reset history state that removes only the selected tab contribution while preserving later unrelated work.
- This must be corrected before the same reset pattern is reused by additional connected tabs.

### UI-Only Retouch Tabs

- `Skin`, `Blemish`, `Wrinkle`, `Makeup`, and `Hair` currently hold UI values and reset their controls.
- They do not yet dispatch preview or commit requests into the image-processing path.
- `Face Shape`, `Face Detail`, and `Background` already have user-facing preview/commit routes.

- Current validation depends on build checks, worker warmup, app smoke checks, and project-director visual review.
