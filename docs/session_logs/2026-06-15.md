## Replace Or Isolate

- Replace meaning-blurred names such as `BackgroundSubjectMask`.
- Do not treat parsing background as the final authority.
- `ParsingBackgroundMask` may be a helper candidate only.
- `PersonMask` is the authority for background replacement.
- Avoid `PreviousPreview -> NextPreview` as an input route.
- Gather coordinate transforms into one owner instead of scattering them through preview paths.
- Prevent individual tabs from owning or overwriting final preview output.

## Canonical Background Rule

- `PersonMask` means final visible person-preserve mask.
- `PersonMaskRaw = BioMask union ClothingMask union AccessoryMask`.
- `PersonMask = FillSmallInternalHoles(PersonMaskRaw, maxArea, enclosedOnly)`.
- Small enclosed internal holes are mask errors and should be filled.
- Structural background gaps such as crossed-arm gaps, finger gaps, and arm-body gaps are real background and must not be filled.
- `PersonAlpha` is the compositing alpha for preserved visible person regions.
- `BackgroundMask = 1 - PersonAlpha`.
- Background replacement is:
  - `Foreground * PersonAlpha + NewBackground * (1 - PersonAlpha)`.

## Work-Area Rule For All Sliders

- A slider must not blindly follow the current preview image.
- A slider must not blindly follow a head mask.
- Every slider needs an explicit purpose-based work area.
- The general flow is:
  - `UserIntent`
  - `OriginalImage-based WorkArea`
  - size check
  - optional `WorkAreaProxy`
  - local mask calculation
  - apply/protect/block mask routing
  - user amount
  - preview result
- The user chooses how much.
- The engine chooses where, which work area, which masks, and which protection rules.

## Proxy Rule

- Work areas are defined from the original image coordinate space.
- If the original is large, crop the original work area first.
- Then create a proxy only for that work area when needed.
- Full-frame tasks use a full-frame proxy.
- Local tasks use a local work-area proxy.

Examples:

- Background replacement:
  - work area: full image
  - proxy policy: full-frame proxy
  - reason: full visible person silhouette is required
- Double chin:
  - work area: chin-centered under-jaw and upper-neck area
  - proxy policy: local work-area proxy
  - reason: only chin, jawline, and upper neck are needed
- Lips:
  - work area: mouth-centered lip, mouth-corner, and orbicularis area
  - proxy policy: local work-area proxy
  - reason: lip boundary and mouth corners need local precision
- Eyes:
  - work area: separate left-eye and right-eye areas
  - proxy policy: local work-area proxy
  - reason: bilateral geometry must stay independent

## Double-Chin Direction

- Double-chin work starts from the chin center, not from the whole neck.
- Build a chin-centered work area first.
- Inside that work area, calculate:
  - `SubmentalRegionMask`
  - `DoubleChinMask`
  - `JawlineMask`
  - `NeckBioMask`
  - `ClothingMask`
- The tool should prepare the work area and masks.
- The user decides strength and operation amount.
- Document-aligned formula:
  - `DoubleChinMask = UnderJawROI intersect NeckBioMask intersect Below(JawLine) intersect Above(NeckBaseLine) * DoubleChinProb`
  - `DoubleChinWorkMask = DoubleChinMask * (1 - BeardMask) * (1 - ClothingMask) * (1 - AccessoryMask)`
- `JawlineMask` is a boundary/reference/protection structure, not the whole lower jaw.
